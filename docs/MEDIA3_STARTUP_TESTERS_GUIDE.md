# 🧪 CharmIPTV Phoenix — Startup and playback testers' guide

## Test candidate after Build 130 · August 28, 2026

Test on the **Onn 4K box, NVIDIA Shield and Fire TV Stick**, recording the exact model, OS version and APK build from **Settings → About → Android build**. Install the new owner-supplied APK over Build 129 or 130 first; keep settings and favorites so upgrade retention is tested. If Android rejects the upgrade, report the message instead of uninstalling. Do not clear app data unless separately requested.

**Start with items 28, 1, 3 and 7 on each TV.** Then work through the rest.

Each item explains the feature, the action to try and the expected result. Mark PASS/FAIL/NOT TESTED and record the time of any failure. Use NOT TESTED if the required source, track or device tool is unavailable. Open **Quick Actions** using its fullscreen button or a long OK/Select press on the player/Guide. The remote's Play/Pause hardware button can be remapped, so pause tests use the onscreen Play/Pause control.

- 📺 **1. Sustained live playback.** Keeps one Media3 session running through ordinary playback. **Test:** watch the channel that previously hiccupped for at least 20 minutes without touching controls. **Pass:** no unexplained restart, permanent black screen or frozen controls. Record the interval and duration of any small pause.
- 🌊 **2. Repeated brief interruptions.** Brief buffering should wait for data rather than count as a failure. **Test:** observe at least ten natural interruptions on the problem channel; if practical, briefly disconnect and restore this device's Wi-Fi three times. **Pass:** no second/third-interruption cutoff or player switch. A network disconnect is a separate recovery test, not an exact reproduction of provider jitter.
- 🚪 **3. Exit to Favorites.** Releases playback before returning focus to the list. **Test:** play from Favorites for several minutes, close any open menus, then press Back until playback exits and immediately navigate the list. The first Back may reveal controls. Repeat ten times. **Pass:** responsive D-pad navigation, no minute-long lockup, no leftover player audio.
- 🏠 **4. Minimize and return while playing.** Pauses/resumes the current fullscreen session. **Test:** press Home, wait 10–30 seconds, reopen CharmIPTV; repeat five times, including once with Quick Actions open before Home. **Pass:** picture and sound return without a new channel selection, and remote controls/navigation remain usable.
- ⏸️ **5. Manual Pause survives backgrounding.** Respects explicit pause intent. **Test:** use the onscreen Pause control, go Home, reopen the app, choose Quick Actions → Aspect ratio, then use onscreen Play. **Pass:** it remains paused until Play; aspect changes do not resume it.
- ⚡ **6. Channel switching.** Serializes source ownership and ignores old callbacks. **Test:** change channels rapidly twenty times, including during loading. **Pass:** the final selected channel owns picture, sound, labels and controls; no overlapping audio.
- 🗓️ **7. Guide preview → fullscreen → Guide.** Transfers one native player owner. **Test:** select a Guide channel, use the preview rail's Play button, then return using the fullscreen Guide control, Back or Quick Actions → Open TV Guide. Cover each exit route across ten repetitions. **Pass:** the expected group/channel is restored and only the visible player produces audio.
- 💤 **8. Background the Guide.** Stops hidden Guide clocks, queued reads and preview work. A running bridge read may finish within its existing bounds; stale results must not revive the UI. **Test:** scroll quickly, immediately press Home, wait 30 seconds, then return and navigate. **Pass:** no stale preview starts in the background; the selected neighborhood reloads and responds.
- 🧩 **9. Guide during fast transitions.** Discards late programme-loading results and checks alternate exits. **Test:** scroll several pages and immediately leave for Favorites or Settings, then return. Also enter fullscreen and leave through Quick Actions → All Settings, then visit Favorites. Repeat with a large playlist. **Pass:** no delayed focus jump, leftover playback audio, stale channel selection or long navigation freeze.
- ⭐ **10. Favorite the current channel after zapping.** Regression check for current-channel matching; the shared fingerprint helper is defensive cleanup. **Test:** note A and B's favorite status, open A, zap to B and wait for playback. Open Quick Actions, confirm its heading names B, then use Add Favorite or Remove Favorite and inspect Favorites. **Pass:** only B's favorite status changes; A is unchanged.
- 🧭 **11. Main drawer focus.** A closed drawer cannot trap remote input. **Test:** repeatedly open/close the drawer from Guide, Favorites and Settings, then navigate each page. **Pass:** focus is visible and does not disappear into an offscreen menu.
- ↔️ **12. Guide groups and selection restore.** Preserves useful selection and focus state. **Test:** change groups, move Right to later programmes, open/close the Groups and main drawers, then enter fullscreen from the preview rail and return. **Pass:** focus is visible at the expected group/channel, programme times remain valid and D-pad movement stays orderly.
- 🪟 **13. Programme menu lifecycle.** Closes stale overlays and restores current-route input ownership. **Test:** select a programme cell to open Program Quick Actions, go Home, reopen, then visit Favorites. Repeat after setting/cancelling a future programme's reminder, allowing notification permission if prompted. **Pass:** no invisible modal blocks the next page and no old action updates a new programme. The current Guide opens Program Quick Actions, not a separate Program Details screen.
- 🔎 **14. Quick Actions EPG search.** Ignores results from a closed or replaced search. **Test:** with a configured/refreshed custom EPG, open Guide Quick Actions → Assign custom EPG → a source, type a search, then immediately close using the X. Select another channel and repeat. **Pass:** the new menu shows its selected channel/source/query; old search results do not appear later. Closing the search must not assign anything.
- 🎮 **15. Busy settings buttons.** Keeps focus visible while suppressing duplicate activation. **Test:** choose Settings → Health → Export diagnostics and press OK again while it says Working…. Separately repeat Settings → EPG → Refresh EPG only now. **Pass:** no duplicate operation or lost focus; other available controls remain navigable. Cache report/prune buttons do not show this busy state.
- 🧹 **16. Cache report and pruning.** Runs slow filesystem work away from the native control queue. **Test:** in Settings → Health, choose Report cache storage, then Prune old disk cache; navigate away/back and play a channel afterward. **Pass:** no permanent UI lock; saved favorites/settings and provider access remain intact. The report measures disk usage, not RAM.
- 🧠 **17. Memory over repeated use.** Releases offscreen work while retaining bounded useful caches. **Test:** perform twenty Guide/Player/Favorites cycles and compare responsiveness before and after settling. If process-memory tools are already available, attach comparable RAM readings. **Pass:** no crash or worsening navigation delay; optional RAM readings should not show continuing growth toward exhaustion. Health's cache report cannot measure RAM, and one higher cached-memory reading alone is not a leak.
- 🍪 **18. Provider session continuity.** Keeps cookies without periodic cache flushes. **Test:** use a provider/channel requiring login cookies, play for 20 minutes and change channels repeatedly. **Pass:** no new authorization failures caused by navigation. Report status codes, never passwords, URLs or cookie values.
- 📡 **19. Network recovery.** Reopens recoverable sources inside Media3 with paced retries. **Test:** disconnect this device for about 10 seconds and reconnect. **Pass:** playback can recover without VLC or repeated manual Retry; invalid credentials are still reported clearly.
- 🧱 **20. Buffer profiles.** Trades latency for buffering headroom with memory limits. **Test:** use fullscreen Quick Actions → Buffer size to try Small, Medium and Large on the same channel, allowing each explicit change to settle. The same options are in Settings → Player. **Pass:** all profiles can play; changing a profile may deliberately rebuild playback, but it must not cause ongoing restarts.
- 🖼️ **21. Aspect ratio and preview mute.** Changes presentation without an unrelated Resume. **Test:** repeatedly choose fullscreen Quick Actions → Aspect ratio to cycle Fit/Fill/Zoom/Stretch while playing and paused; separately use Mute/Unmute on the Guide preview rail. **Pass:** picture sizing and mute work, paused video stays paused, and no player switch occurs.
- 🔊 **22. Audio and subtitles.** Selects supported tracks on the current channel. **Test:** on a channel providing multiple tracks, choose fullscreen Quick Actions → Audio / subtitles, change audio track and toggle subtitle tracks/Off, then switch channels. **Pass:** available supported choices work, controls refresh for the new channel and no old track selection freezes playback. This does not test native subtitle size/background styling, which is not implemented.
- 📴 **23. Preview hide/off.** Stops a preview that should no longer be active. **Test:** set Settings → General → Live preview to Off and return to Guide; restore Normal. Separately test Hide/Show on the Guide preview rail or Settings → Appearance → Hide guide preview. **Pass:** no hidden preview audio; preview returns only when allowed.
- ⏰ **24. Sleep and explicit Stop.** Intentional stop controls remain supported. **Test:** keep Settings → Player → Sleep timer Off during stability tests. Separately select 15m, watch until it expires, then test fullscreen Stop and Back. **Pass:** the timer exits playback after about 15 minutes (checked every 15 seconds), explicit Stop/Back works, and the next screen responds.
- 📚 **25. Playlist and EPG refresh.** Updates the catalog without reviving hidden Guide work. **Test:** use Settings → EPG → Refresh playlist & EPG now, navigate away during loading, then return to Guide and play a favorite. **Pass:** refreshed channels/programmes appear, favorites remain and old queued work does not lock playback or navigation.
- 🛑 **26. Unsupported or unavailable channel.** Reports unsupported/fatal failures while recoverable outages may continue retrying in Media3. **Test:** open a known unavailable channel, then select a working one or exit. Test a known unsupported protocol separately if supplied. **Pass:** unsupported protocols show an error, there is no VLC fallback and navigation remains usable during error/retry states. If a player-stop failure occurs, Back should still return to the list and Guide should explain that cleanup is pending. Press Play to try again: it must start only after native release is acknowledged, or show a clear message without navigating into an empty player. If it remains blocked, force-stop CharmIPTV in Android's app settings and reopen it; do not clear data. Mark this release-failure part NOT TESTED if no such failure occurs.
- 📦 **27. Upgrade and settings retention.** Keeps the existing sideload installation identity. **Test:** upgrade from Build 129 or 130 without clearing data, reopen the app and inspect favorites, Guide settings, audio preferences and buffer profile. **Pass:** expected saved choices remain and no VLC option reappears.

- 🚀 **28. Cold launch and first channel.** Checks the Build 130 black-screen regression from a fresh process. **Test:** after upgrading, force-stop CharmIPTV through Android app settings (do not clear data), reopen it and try the first Guide preview, then fullscreen. Repeat a cold launch and go directly to Favorites or Live TV → Play without first using the Guide preview. **Pass:** a known working source produces video and audio on both paths; controls and Back remain usable. Record whether any failure happened before the first picture or only after switching.
- 🌿 **29. Routine memory warnings during playback.** Native and JavaScript share the startup grace; light pressure must not cancel a visible preview. **Test:** if existing developer tools can send Android running-moderate/low memory notifications, send them during initial preview preparation and again during established playback. Otherwise mark NOT TESTED; do not install a RAM-stress app or fill storage. **Pass:** the pending/playing channel is not stopped, no new tune is requested, and ordinary Guide navigation still works.
- 🛟 **30. Critical memory pause and intentional resume.** Allows Android to free preview resources without leaving an unexplained black pane or a retune loop. **Test:** only with existing developer tools, send a critical memory notification while the Guide preview is active. Stay on the same channel through an EPG refresh, then select another channel or use Play. Separately test Home → reopen. **Pass:** the Guide keeps the selected channel and shows “Preview paused to free memory”; refresh alone does not restart it. An intentional selection/Play or foreground return can resume when native ownership allows it. A release fault shows the cleanup message instead. Mark NOT TESTED without these tools.
