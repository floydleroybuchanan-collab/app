# RC.10 viewing and settings update

Multiview uses stable native player slots with a separate visual order. Menu, picker, swapping and enlargement stay inside the multiview route. Enlarged panes remain attached; other panes continue running, so enlargement does not reduce provider connection usage. Up to four decoders retain the existing 12 MiB-per-player buffer targets, startup deadline, release ownership barrier, lifecycle cleanup and memory-pressure handling. Those buffer targets are not a total RAM limit.

The channel picker is virtualized and uses the current combined enabled catalog. Favorites/recent filters use channel IDs. Hidden channels and locked provider groups cannot be opened through the picker. Remembered arrangements contain at most four IDs, never saved stream URLs; missing channels are skipped on reopening. Audio/caption choices retain language and label hints across native recreation. Remote Back closes picker/menu first, then enlargement, then exits playback. Native Android testing is required for focus restoration and concurrent hardware decoding.

All Playlists is first in the guide and selects all enabled catalogs directly. New installations default to all playlists; existing explicit choices remain saved. The guide shows active playlist, enabled count, catalog count and EPG filtering. Each playlist links to its group settings. Hiding a group hides its tab, not the channels in All/search; new provider groups are visible after refresh. Per-playlist automatic hiding of newly discovered groups is not implemented.

Player buffer controls and guide scheduling/matching controls are under Advanced. The existing settings owners, import scheduling, cache limits and player implementation remain authoritative. Help & Health links to the relevant screens. VOD sources have type/resolution/cloud-ready filters, compact titles and full details on hold/long press or Details. Readiness remains separate from decoder compatibility.

Backups have explicit coverage. Basic settings/favorites export only allowlisted keys, with no playlist files, recent-channel objects or secure credentials. Full Live TV backups use AES-256-GCM, a random salt and nonce, and PBKDF2-HMAC-SHA256 at 210,000 iterations. An equivalent portable HMAC implementation supports older Android providers. Encryption is serialized off the UI thread with bounded input. The password is not persisted. Restore authenticates before parsing and confirms coverage before writing. Legacy plaintext backups remain importable. VOD history/preferences, Real-Debrid credentials and app login are excluded; parental PIN is not transferred. Restore does not change the destination device's secure PIN. Restart after restore to reload cached preference snapshots.

Validation: frontend unit tests, TypeScript, ESLint, native configuration and guide architecture checks; backend tests; repository playback scan; Android compilation, unit tests and API compatibility lint in the sideload workflow. Device checks still needed: D-pad/touch menus, two/three/four-pane layouts, swap/enlarge/Back, cloud-source filters, failed/disabled providers, background/resume, low-memory handling, encrypted export/import and cancellation.

The saved bot help content must be updated only after the RC.10 APK is available. Preserve unrelated admin content and record the previous app-help entry before updating it. Do not send a group announcement as a deployment side effect.
